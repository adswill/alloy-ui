# Decisions

1. **Crate names**: `alloy-ui-{core,layout,render,theme,widgets,platform,ipc,cli}`; all returned 404 on crates.io on 2026-11-20. Directory names are short (`crates/core`).
2. **Geometry, DrawCommand and Event live in core.** Layout, render and widgets all need them; a separate types crate adds a hop for no gain yet.
3. **Widgets draw into a `DrawList`, not a generic renderer.** Keeps the renderer swappable and tests headless. Cost: no per-widget custom GPU pipelines; revisit if needed.
4. **Zero dependencies in the contract stubs.** wgpu, winit, cosmic-text etc. are added by the crates that own them.
5. **Release profile is size-first** (opt-level z, fat LTO, panic abort, strip) to hit the 10 MB counter target.
6. **Visual direction**: follow Impeccable's AI-slop catalogue; see DESIGN.md.
7. **Facade crate `alloy-ui`** (`crates/alloy`) owns the glue: shell events -> `Runtime` -> `WindowRenderer`, background futures through `ipc::TaskRunner` whose waker is the shell proxy. Apps depend on it only. Layouter is a parameter so core stays independent of the layout crate.
8. **Platform PR #1 merged locally by the lead**, verified fmt/clippy/tests on Linux only; Windows and macOS await CI.
9. **Contract change (lead):** `DrawCommand::Text` gained `weight` and `line_height`; new `DrawCommand::Line` for strokes (renderer draws it as a chain of round dots for now; a proper SDF segment is a later optimisation). `Event::Tick(ms)` plus `Widget::animating()` give widgets a timer only while something animates; `Outcome.tick` tells the shell to schedule ~16 ms ticks, so an idle app has no timer.
10. **Weight, line height and family are honoured by the renderer** (CPU and GPU share one shaping path). `DrawCommand::Text` carries `weight`, `line_height` and `family` (Sans or Mono); `TextMeasurer` measures with the same shaper so layout matches drawing.
11. **Licence: MIT OR Apache-2.0** (the Rust norm; permissive, unlike a GPL/commercial split). `LICENSE-MIT` and `LICENSE-APACHE` at the root; every crate inherits the workspace licence field.
12. **Bundled fonts**: IBM Plex Sans (400/500/600/700) and Plex Mono (400/500), OFL 1.1, so text is identical on every OS. Inter and Geist are avoided on purpose (listed as AI-look tells in DESIGN.md).
13. **CJK and emoji fallback uses system fonts**, not bundled ones: a CJK font is 5-15 MB and would break the 10 MB binary target. cosmic-text falls back per glyph; if no system font covers a script the glyph is missing. Revisit with an optional `cjk-fonts` feature.
14. **CI**: integration-branch runs are never cancelled, and `push` triggers only on main and the lead branch, because runners start 10-15 minutes late and cancel-on-push meant nothing finished.
15. **Platform: multi-window keys are chosen by the caller** (`WindowKey(u64)`, `MAIN` = 0), so the app, facade and shell agree on identity without a mapping step. Windows are created at the end of the callback that asks for them. The loop exits when the last window closes.
16. **Platform: Wayland clipboard uses data-control, not `wl_data_device`**, over its own connection, via `wayland-client` plus the generated protocol crates `wayland-protocols` and `wayland-protocols-wlr` (same family; no GUI toolkit). Reason: see crates/platform/README.md. Tested against sway 1.9 only.
17. **Platform: Windows file dialogs use the `windows` crate (0.58)** for COM interfaces; `windows-sys` has no interface wrappers and hand-written vtables would be untestable here. Menus, tray and clipboard stay on `windows-sys`. Lead accepted this: the `windows` crate is Microsoft's official binding, from the same metadata as `windows-sys`, so it fits the brief's "platform bindings" allowance; it is not a GUI toolkit.
18. **Concise app API lives in the facade, built on the existing widgets** (`crates/alloy`, `alloy_ui::prelude`). No change to core or widgets was needed. Three mechanisms remove most boilerplate:
    - *Ambient `Ui`*: the facade stores the window's `Ui` in a thread-local while `view`/`update` run, so widget helpers (`button("x")`) take no `&ui`, and the `Root` + page-background wrapper is added by the shell. Cost: helpers panic if called outside `view`/`update` (the message says so); tests use `testing::Harness`. Single-threaded by design, which the `Rc`-based `Ui` already forces.
    - *Automatic ids* from `#[track_caller]` call site plus an occurrence counter reset on every view. Focusable widgets and scroll areas get stable state across rebuilds with no `.id(n)`. Limitation: the same call site in a loop is identified by order, so reordering a list of inputs moves their focus/scroll state. Use `.id()` for that case. Ids have the top bit set so they never collide with hand-picked small ids.
    - *One `Node<M>` type and a `View<M>` trait* implemented for everything that converts into it (builders, `&str`, `String`, `Option`), so `col![..]` takes mixed children, `None` is empty, and `fn view(&self) -> impl View<Msg>` is a short signature. Sizing/padding/background methods are on the trait and share one `Boxed` container instead of nesting.
19. **Two app styles, both typed.** `App` is the Elm contract (messages, `update`, commands, subscriptions); `sketch(state, view)` uses `Act<S>` (an `Arc<dyn Fn(&mut S)>`) as the message type so handlers are closures and there is no enum. Closure messages are not inspectable or serialisable, which is the price; apps that want a message log use `App`. `.bind(|s| &mut s.field)` writes a widget's value into a field without a closure body. Rust cannot infer the state type for field access in nested closures, so `.bind` and `.act` closures that touch fields need a `|s: &mut State|` annotation (a short alias helps); closures that only deref (`|n| *n += 1`) infer fine.
20. **`App::update` returns nothing; `update_cmd` returns a `Cmd`.** An `impl Into<Cmd>` return type tripped the `refining_impl_trait` lint for every implementor, so commands get their own method with a default that calls `update`.
21. **Honest numbers over a slogan.** The target was 4x to 10x fewer lines than iced; the measured result on five apps is about 1.8x (BENCHMARKS.md), 2.2x on the pure-UI counter. Further wins need higher-level built-ins (a data table, form layouts, local view state), not more syntax. Listed as next steps rather than claimed.
22. **`--headless [file.png] [--click text]..` is built into `App::run_sized`**, so every app can produce a screenshot in CI with no extra code, using the same runtime and CPU renderer as the other examples.

## Text editing follows grapheme clusters, UAX #29 words and per-OS shortcuts

- Caret and selection stay `char` indices (so the controlled-value API is unchanged) but every move, delete and hit test lands on a grapheme-cluster boundary. Depends on `unicode-segmentation` (data tables only, no GUI code), the one new dependency in `alloy-ui-widgets`.
- Words use UAX #29: `don't` and `foo_bar` are one word, and each CJK ideograph is its own stop (no dictionary segmentation yet).
- Hit testing binary-searches boundaries with prefix widths (O(log n) measurements) rather than measuring every prefix.
- Shortcut key: Cmd on macOS, Ctrl elsewhere (Super and Ctrl+Alt/AltGr never act). Word moves: Option on macOS, Ctrl elsewhere. On macOS Ctrl+A / Ctrl+E mean line start / end. Chosen at compile time with `cfg!(target_os)`.
- While an IME preedit is active the field consumes every key except Tab, so Backspace, arrows, Enter and shortcuts cannot touch committed text.
- Bidi is basic: a line whose first letter is right-to-left makes plain Left/Right arrows move logically forward/backward respectively. Word and line moves stay logical, and the caret's drawn position is still LTR-only. Full visual bidi needs `unicode-bidi` plus renderer support.
- The editor selects a word on double click and a line on triple click (500 ms, 4 px). The single-line input does not yet. A lone CR on paste is a newline.
24. **Platform: multi-window keys are chosen by the caller** (`WindowKey(u64)`, `MAIN` = 0), so the app, facade and shell agree on identity without a mapping step. Windows are created at the end of the callback that asks for them. The loop exits when the last window closes.
25. **Platform: Wayland clipboard uses data-control, not `wl_data_device`**, over its own connection, via `wayland-client` plus the generated protocol crates `wayland-protocols` and `wayland-protocols-wlr` (same family; no GUI toolkit). Reason: see crates/platform/README.md. Tested against sway 1.9 only.
26. **Platform: Windows file dialogs use the `windows` crate (0.58)** for COM interfaces; `windows-sys` has no interface wrappers and hand-written vtables would be untestable here. Menus, tray and clipboard stay on `windows-sys`.
27. **Platform: accessibility is a platform-neutral tree plus one adapter per OS, no AccessKit.** `access.rs` defines `AccessTree`/`AccessNode`/`AccessRequest` (own types, so `alloy-ui-platform` does not depend on the widgets crate; the facade maps `widgets::A11yNode` onto them). `ShellContext::set_accessibility(&tree)` is called after each frame; adapters diff against the last tree and publish only changes. Screen-reader requests (press, focus, set value, increment, decrement) come back as `PlatformEvent::Accessibility { window, request }`. Linux speaks AT-SPI2 over the crate's own D-Bus client (`dbus.rs`), macOS subclasses `NSAccessibilityElement` and adds a mouse-transparent `NSView` over the content view, Windows subclasses the HWND and answers `WM_GETOBJECT` with UI Automation providers (uses the `windows` crate, see 13).
28. **Platform: key events are dropped while an IME preedit is showing.** winit can still deliver raw `KeyboardInput` during composition on some backends; the shell tracks the preedit state and swallows those events so a widget never sees Backspace or Enter that the IME already consumed. The commit arrives as `TextInput`.
29. **View-local state (`local`)**: `let q = local(String::new())` is keyed by call site and lives in a thread-local slot map in the facade, not in app state. Widgets write to it with `.local(&q)`; any handler can `q.set(..)`. Setting it goes through a no-op `Act`, so the normal update-then-view cycle redraws. Slots are never freed (a few bytes per call site; a view that creates call sites dynamically is not a pattern we support). It is thread-local like the ambient `Ui`, so multi-window needs one slot map per window; the facade is single-window today.
30. **`table` is Act-only and sizes columns from content.** Sorting and search live in `local` state, so the table needs a message that can touch it, which `Act<S>` provides; Elm-style `App`s can use the widgets crate's `Table` directly. Columns are `Fixed` from the widest cell (6.6 px per character plus padding, clamped 70 to 200) because several `Fill` columns collapsed to content width in a narrow table and a lone `Fill` column collapsed to zero; the underlying layout behaviour is worth a look from the layout owner. Header cells are sort buttons, via a new the widgets crate's own `on_sort`/`sorted` header (merged from the widgets thread); table rows now centre cells vertically.
31. **`#[derive(Record)]` (crate `alloy-ui-macros`, free on crates.io 2026-11-20)** gives a struct a field list (`FIELDS`), `get(i)` and `set(i, Value)`. The control comes from the type (`String` text, `bool` checkbox, number slider) and `#[form(email, required, range = (a, b), step = s, choices = CONST, label = "..", skip)]`. The helper attribute is `form` because a `field` attribute clashed with the `field()` function in the prelude. A runtime schema keeps the macro tiny (about 140 lines, one pass over the fields) at the cost of a per-frame `get`/`set` match rather than static dispatch.
32. **Persistence is opt-in on `sketch`**: `.persist("name")` loads `<config dir>/name/state.json` at start and rewrites it (temp file then rename) after every message. It serialises the whole state with serde_json, so transient fields (search text) belong in `local`, not in state. No migration story yet: a file that fails to parse is ignored and the initial state is used.
33. **Honest 10x status.** Same-app ratio vs idiomatic iced on a 300-line app is 6.6x, and about 15x for a pure record editor; see BENCHMARKS.md. Remaining ideas that would move the same-app number: async loading states, built-in settings page, routing derived from the page enum, and an `App`-style `records`.
31. **Layout: a `Shrink` container holding a `Fill` child becomes `Fill` on that axis** (iced's `Length::fluid` rule). Root cause of the "Fill columns collapse in a narrow table" report: the engine let a `Fill` child inside an auto-sized parent fall back to its content size, so a row of `Fill` columns in an auto-sized column never saw the space on offer. Fixed in `alloy-ui-layout` (`Node::length`, also used for the root); tests added; the widgets `list_light` golden regenerated because a list in a shrink page now fills it. The facade's `table` workaround (sizing columns from content) can now go.

34. **Pages own their state (`app(title).page(name, || view)`)**. Each page's state lives in `store`s (like `local`, but saved), keyed by page name plus call order; `.persist()` writes them all to `<config>/<title>/state.json`. `store_as(name, ..)` is the shared variant (used for the theme and settings). This removes the state struct, page enum, view function and lenses from multi-page apps. Cost: state is not one inspectable value, so apps that want a message log or shared mutable state still use `sketch`/`App`.
35. **`Local<T>` is a `Copy` handle** (an id into thread-local slots), not an `Arc`: closures capture it without `.clone()`. It must be used on the thread that made it (the UI thread; handlers and the resource pump run there).
36. **`#[derive(Record)]` picks controls from the field type** through the `Field` trait (`String`, `bool`, numbers, any `choices!` enum), implements `Serialize`/`Deserialize` itself (missing keys keep their `Default`, so adding a field does not lose saved data), treats the first field as the required title and a field named `email` as an email. `#[form(..)]` overrides. Do not also derive serde on a `Record`.
37. **`resource(fetch)`** runs `async fn() -> Result<T, E: Display>` on a background thread with a std-only executor, applies the result on the UI thread via a pump subscription (50 ms while a fetch is in flight, 500 ms only if auto-refresh is on, nothing when idle), keeps old data visible during refresh, and renders Loading / error card with Retry / data from `.show(..)`. Chosen over a core change so no runtime edits were needed; a proper wake from the task thread (instead of polling) would be better and is a lead-thread item.
38. **`space()` fills width only**, `vspace()` height. After the layout fix (31) a both-axes filler inside a row stretched the row to fill the page, so the header row ate half the height.
39. **Honest status after pass 3:** record-editor-shaped apps reach 11.7x (admin) and 16.6x (crud-only); apps with their own logic sit at 2.4x to 3x. Further wins need to come from reducing handler and layout code in general, not more data-shaped blocks.
40. **Cells, not message plumbing.** `Cell<V>` (`Local<V>` or `Item::field(lens)`) is the one thing widgets bind to; lenses are plain `fn` pointers so handles stay `Copy`. Widget shortcuts live on extension traits (`TextCell`, `FlagCell`, `ChoiceCell`). The flag switch is `.switch()` because `Local<bool>::toggle()` already flips.
41. **`browse` keys the detail pane per row** with `cx::keyed`, which salts every generated id and `local`, so each row has its own cursor, scroll and confirm state.
42. **Pinning is a list convention**, not user ordering: `.pin(..)` shows a star and sorts pinned rows first, and `.order(..)` only breaks ties.
43. **Audit of the 10x claim.** Same-block apps (admin, status, notes) reach 9x to 14x; three new apps no block was built for reach 1.5x to 1.8x (1.6x total), and a compact iced status rewrite is 20% shorter than the original. Public wording: "about 1.6x on ordinary apps, 9x or more when the app is a table, form or list". See BENCHMARKS.md.
44. **`at!(s.field)` is a witness macro, not a lens derive and not a pointer offset.** The macro passes `&*s` only to fix the state type, so closures need no annotation, and builds an ordinary `Fn(&mut S) -> &mut T`. Considered and rejected: a derive generating `Struct::field` accessor fns (extra attribute on every state type, name clashes) and computing a byte offset from `&mut s.field` (unsound with enum payloads: a handler queued after the variant changed would write through a stale offset). Widget constructors take `impl Val<T, M>`: a plain value stays read-only, a `Place` also installs the handler.
45. **Everyday-app ratio is 2x to 3.3x, not 4x.** After bindings, `.page()`, `tick_while`, `wizard`, `fs`, `valid`, table helpers and `number`/`stepper`, the three audit apps go from 1.6x to 2.9x and a fourth unseen app is 2.1x. What remains is state, domain logic and rustfmt line breaks. Public wording stays "about 2x to 3x on ordinary apps, 9x or more on apps that are a table, form or list".
46. **File access goes through `alloy_ui::fs` and the existing `CapabilitySet`.** Unrestricted by default (so examples need no config); `fs::grant(set)` turns on `fs_read`/`fs_write` scope checks for every helper. Directory listings are cached per path and invalidated by the directory's mtime, so `view` can call `fs::list` every frame.
47. **CI: PRs run Ubuntu only, the three-OS matrix runs on pushes to the integration branch and `main`.** With about 20 thread branches each producing a PR run and a push run per commit, macOS and Windows jobs queued for 1.5 to 2 hours and Ubuntu/macOS jobs were marked failed without ever getting a runner (no steps, no logs). Thread branches no longer trigger push runs at all. The integration branch is pushed about once an hour so its full run is not starved. Windows passed fmt, build, clippy and tests on runs 73 and 75; Ubuntu and macOS were still unverified at the time of this decision.

## Cache text shaping inside `TextSystem`

Shaping with cosmic-text cost about 150 us per string, paid on every layout pass (measure) and every frame (glyph layout in `flatten`). Both are now memoised in `TextSystem`, keyed by a hash of content, size, weight, family, line height and wrap width, with the stored content compared on a hit so a hash collision cannot return wrong glyphs. Glyphs are cached relative to the box origin (which is rounded to whole pixels anyway), so one entry serves every position. Each map is cleared when it reaches 4096 entries, a crude bound chosen over LRU bookkeeping because a window rarely shows that many distinct strings and a miss only costs one reshape. Result: 400x faster on repeats (see BENCHMARKS.md). Not done: removing the wgpu `gles` feature (saves 0.38 MB but loses the GL fallback).
48. **Tighten pass (no API or behaviour change).** Checkbox, switch and radio share `util::activation` (press/release/Space) and `util::control_label`; `TextInput` and `TextEditor` share `commit_edit`/`history_edit`. `crates/alloy` `dsl.rs` and `blocks.rs` became directory modules (`dsl/{mod,values,choices}`, `blocks/{mod,table,pages,wizard}`) with the same public re-exports. Library `Mutex::lock().unwrap()` in `alloy` and `ipc` became a poison-tolerant `lock_ok()`, so a panicking worker thread can no longer cascade into the UI thread. Every `unsafe` block, impl and fn in `platform` now has a SAFETY comment. Dependency audit: every declared dependency is imported, so nothing was removed and binary size is unchanged. Net line count is slightly positive (comments and helpers outweigh the removed copies); the gain is single-sourced behaviour and smaller files. Left alone on purpose: the `table` block still sizes non-first columns from content (switching to `Fill` would change the gallery goldens); the two example sets (`examples/` Elm-style and `crates/alloy/examples` concise) stay as parallel comparisons.

49. **Pass 7 stays with any-app features.** `state!` is a plain `macro_rules` (no derive, since defaults need only an expression per field). `Wizard::step` counts `field` errors drawn since the last page in a thread-local, so gating follows what is on screen; `page(title, valid, body)` remains for custom rules and resets the count. `field` keeps `Option<&str>` (a generic error type made every `None` ambiguous), so validators that format their message (`min_len`) need `.as_deref()` and `valid::password` is the fixed-text one. `.push/.keep/.clear` are `Btn` methods over `Place`, like `.set/.add`. Measured gain on the four apps is 2.8x to 3.0x.

50. **Dev loop: restart on save, not hot code patching.** `alloy dev` polls file mtimes (no watcher dependency, 250 ms, with a 150 ms settle for save bursts), runs `cargo build --message-format json-render-diagnostics`, and launches the exact binary cargo reports, so killing it kills the app (killing `cargo run` would orphan the child). A failed build keeps the old window and waits for the next save. In-process reload of Rust view code would need dynamic loading and an ABI-stable view boundary, which costs more safety than it gives; `.persist()` makes a restart keep state, which covers most of the benefit. The app gets `ALLOY_DEV=1` and `ALLOY_INSPECT=1`.
51. **Inspector lives in `alloy-ui-core`, driven by the runtime.** It needs the view tree plus layout, which only the runtime holds, and it is a pure function of them. `Widget::debug_name` has a default body using `type_name::<Self>()`, so no widget changed. F12 is handled in `Runtime::handle_window_event` and consumed only when `inspector::available()` (debug build or `ALLOY_INSPECT`), so release apps ship the code but never react. The overlay is part of the draw list, so headless screenshots and tests see it.

## Animation: one clock in `Ui`, springs critically damped by default
- Every animated value lives in `Ui` (per window), keyed by widget position or call site. `Ui::animate` takes any `Animatable` (f32, Point, Color premultiplied) and a `Transition` (eased tween or spring); `ease`, `ease_with`, `spring` and `presence` are thin wrappers. Retargeting continues from the current value, and springs keep velocity.
- Springs default to `SNAPPY` and `GENTLE`, both critically damped (no overshoot), matching DESIGN.md's ban on bouncy motion. `LIVELY` (damping ratio 0.7) exists but is opt-in.
- Reduced motion (`Ui::set_reduced_motion`, or env `ALLOY_REDUCE_MOTION=1`) makes every transition jump, so nothing ticks. There is no portable OS query in our platform layer yet; wiring the macOS, Windows and GTK settings in is a follow-up.
- Idle stays at 0%: `Ui::animating` is false when all tweens and springs are settled (fixed a latent bug where a freshly created tween counted as running for its duration).
- Views that read animated values (`animated`, `spring`, `reveal`) must be rebuilt each frame, so the runtime now rebuilds the view on a `Tick` that nothing consumed. Ticks only flow while something animates.
- Enter and exit: `Reveal` fades, drifts up 6 px and optionally collapses height, then stops drawing once an exit has played. Group fade is done by scaling alpha per primitive (`fade_translate`), exact for non-overlapping content; images do not fade yet.
- Micro-interactions: button press is eased (45 ms in, 120 ms out) with a 1 px label press, button focus ring fades in, slider thumb swells on a spring (1.08 hover, 1.14 grab).
- Not done, on purpose: backdrop blur (needs a render-target copy on the GPU path and a separable blur on CPU; DESIGN.md also discourages glassmorphism), animated gradients, layout transitions between arbitrary siblings (only `Reveal` collapse).

## Gradients and elevation
- `DrawCommand::GradientQuad` (two stops, angle, radius, border, shadow) is implemented identically on the CPU and WGSL paths: CSS-style gradient line, interpolation in premultiplied space, 4x4 Bayer dither to avoid banding. Facade: `.gradient(from, to, angle)` and `.elevated()` on any view; `Container::gradient`. Use gentle tonal gradients only.

52. **Hot reload is a live markup layer, not hot-patched Rust.** Loading view code as a dynamic library fails three ways: each library carries its own copy of Alloy and so its own thread-locals (the ambient `Ui` a view reads would be missing, unless Alloy became a shared library on every OS), the state type crosses the boundary so adding a field is undefined behaviour, and Rust has no stable ABI so any flag or version mismatch is a crash instead of a message. Instead `live!("ui/x.alloy")` interprets a small indented markup (col, row, text, heading, caption, button, rule, space, gap, theme) into the same `Node` tree, with `{var}` text and `@action` buttons bound from Rust. Under `ALLOY_DEV` the file is stat-ed on a 250 ms timer that exists only then, and a save swaps the tree in place, so state, focus and scroll survive; in release the source is `include_str!`-ed and nothing touches the disk. Parse errors keep the last good tree and show `file: line N: message` in the window. The markup has no loops, conditions or expressions on purpose: dynamic parts stay in Rust beside live parts. Rust edits still restart under `alloy dev` with `.persist()` (decision 50).
53. **Cancellation is a generation counter plus a flag.** `resource_for(key, fetch)` cancels the running fetch when the key changes: the worker's `block_on` loop checks an atomic flag before each poll and the UI thread unparks it, so the future is dropped at its next `.await`. Separately `Resource` carries a generation number, and a finished fetch applies its result only if its generation is still current, so even a future that cannot be interrupted (blocking code) can never overwrite newer data. Debounce needs no API: start the fetch with `sleep`. `reload()` still ignores calls while busy; `restart()` is the cancelling variant. Not done: cancelling `Cmd::perform` futures.
54. **Routing is a typed stack in `local`, not URL strings.** `router(home)` stores past and future route vectors in a view-local slot and returns a `Copy` handle, so handlers capture it freely and it needs no field in the user's state. Routes are the user's own enum, so every screen and its parameters are checked by the compiler; string paths, pattern matching and deep links were left out because desktop apps rarely need them and they trade away that checking. `show` binds `alt+ArrowLeft` and `alt+ArrowRight`. The stack is not persisted (it would need `Serialize` on every route); an app that wants it can keep the route in a `store`.
55. **Test helpers find things by on-screen text.** `Harness` gained `expect*`, `fill`, `wait_for`, `scroll`, `resize`, `texts`, `count` and `snapshot`, all addressing widgets by the text a person sees. Failures print every visible text. `snapshot` reuses the render crate's golden comparison (6 per channel, 0.2% of pixels) at `tests/snapshots/`, updated with `UPDATE_GOLDEN=1`. `chord` now maps multi-letter names (`ArrowLeft`, `F5`) to named keys; before they were sent as characters and never matched.
