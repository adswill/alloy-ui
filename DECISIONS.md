# Decisions

1. **Crate names**: `alloy-ui-{core,layout,render,theme,widgets,platform,ipc,cli}`; all returned 404 on crates.io on 2026-11-20. Directory names are short (`crates/core`).
2. **Geometry, DrawCommand and Event live in core.** Layout, render and widgets all need them; a separate types crate adds a hop for no gain yet.
3. **Widgets draw into a `DrawList`, not a generic renderer.** Keeps the renderer swappable and tests headless. Cost: no per-widget custom GPU pipelines; revisit if needed.
4. **Zero dependencies in the contract stubs.** wgpu, winit, cosmic-text etc. are added by the crates that own them.
5. **Release profile is size-first** (opt-level z, fat LTO, panic abort, strip) to hit the 10 MB counter target.
6. **Visual direction**: follow Impeccable's AI-slop catalogue; see DESIGN.md.
7. **Facade crate `alloy-ui`** (`crates/alloy`) owns the glue: shell events -> `Runtime` -> `WindowRenderer`, background futures through `ipc::TaskRunner` whose waker is the shell proxy. Apps depend on it only. Layouter is a parameter so core stays independent of the layout crate.
8. **Platform PR #1 merged locally by the lead**, verified fmt/clippy/tests on Linux only; Windows and macOS await CI.
9. **Contract change (lead):** `DrawCommand::Text` gained `weight` and `line_height`; new `DrawCommand::Line` for strokes (renderer draws it as a chain of round dots for now; a proper SDF segment is a later optimisation). `Event::Tick(ms)` plus `Widget::animating()` give widgets a timer only while something animates; `Outcome.tick` tells the shell to schedule ~16 ms ticks, so an idle app has no timer.
10. **Weight, line height and family are honoured by the renderer** (CPU and GPU share one shaping path). `DrawCommand::Text` carries `weight`, `line_height` and `family` (Sans or Mono); `TextMeasurer` measures with the same shaper so layout matches drawing.
11. **Licence: MIT OR Apache-2.0** (the Rust norm; permissive, unlike a GPL/commercial split). `LICENSE-MIT` and `LICENSE-APACHE` at the root; every crate inherits the workspace licence field.
12. **Bundled fonts**: IBM Plex Sans (400/500/600/700) and Plex Mono (400/500), OFL 1.1, so text is identical on every OS. Inter and Geist are avoided on purpose (listed as AI-look tells in DESIGN.md).
13. **CJK and emoji fallback uses system fonts**, not bundled ones: a CJK font is 5-15 MB and would break the 10 MB binary target. cosmic-text falls back per glyph; if no system font covers a script the glyph is missing. Revisit with an optional `cjk-fonts` feature.
14. **CI**: integration-branch runs are never cancelled, and `push` triggers only on main and the lead branch, because runners start 10-15 minutes late and cancel-on-push meant nothing finished.
15. **Platform: multi-window keys are chosen by the caller** (`WindowKey(u64)`, `MAIN` = 0), so the app, facade and shell agree on identity without a mapping step. Windows are created at the end of the callback that asks for them. The loop exits when the last window closes.
16. **Platform: Wayland clipboard uses data-control, not `wl_data_device`**, over its own connection, via `wayland-client` plus the generated protocol crates `wayland-protocols` and `wayland-protocols-wlr` (same family; no GUI toolkit). Reason: see crates/platform/README.md. Tested against sway 1.9 only.
17. **Platform: Windows file dialogs use the `windows` crate (0.58)** for COM interfaces; `windows-sys` has no interface wrappers and hand-written vtables would be untestable here. Menus, tray and clipboard stay on `windows-sys`. Lead accepted this: the `windows` crate is Microsoft's official binding, from the same metadata as `windows-sys`, so it fits the brief's "platform bindings" allowance; it is not a GUI toolkit.
18. **Concise app API lives in the facade, built on the existing widgets** (`crates/alloy`, `alloy_ui::prelude`). No change to core or widgets was needed. Three mechanisms remove most boilerplate:
    - *Ambient `Ui`*: the facade stores the window's `Ui` in a thread-local while `view`/`update` run, so widget helpers (`button("x")`) take no `&ui`, and the `Root` + page-background wrapper is added by the shell. Cost: helpers panic if called outside `view`/`update` (the message says so); tests use `testing::Harness`. Single-threaded by design, which the `Rc`-based `Ui` already forces.
    - *Automatic ids* from `#[track_caller]` call site plus an occurrence counter reset on every view. Focusable widgets and scroll areas get stable state across rebuilds with no `.id(n)`. Limitation: the same call site in a loop is identified by order, so reordering a list of inputs moves their focus/scroll state. Use `.id()` for that case. Ids have the top bit set so they never collide with hand-picked small ids.
    - *One `Node<M>` type and a `View<M>` trait* implemented for everything that converts into it (builders, `&str`, `String`, `Option`), so `col![..]` takes mixed children, `None` is empty, and `fn view(&self) -> impl View<Msg>` is a short signature. Sizing/padding/background methods are on the trait and share one `Boxed` container instead of nesting.
19. **Two app styles, both typed.** `App` is the Elm contract (messages, `update`, commands, subscriptions); `sketch(state, view)` uses `Act<S>` (an `Arc<dyn Fn(&mut S)>`) as the message type so handlers are closures and there is no enum. Closure messages are not inspectable or serialisable, which is the price; apps that want a message log use `App`. `.bind(|s| &mut s.field)` writes a widget's value into a field without a closure body. Rust cannot infer the state type for field access in nested closures, so `.bind` and `.act` closures that touch fields need a `|s: &mut State|` annotation (a short alias helps); closures that only deref (`|n| *n += 1`) infer fine.
20. **`App::update` returns nothing; `update_cmd` returns a `Cmd`.** An `impl Into<Cmd>` return type tripped the `refining_impl_trait` lint for every implementor, so commands get their own method with a default that calls `update`.
21. **Honest numbers over a slogan.** The target was 4x to 10x fewer lines than iced; the measured result on five apps is about 1.8x (BENCHMARKS.md), 2.2x on the pure-UI counter. Further wins need higher-level built-ins (a data table, form layouts, local view state), not more syntax. Listed as next steps rather than claimed.
22. **`--headless [file.png] [--click text]..` is built into `App::run_sized`**, so every app can produce a screenshot in CI with no extra code, using the same runtime and CPU renderer as the other examples.
